# 首课：从一个 token 的概率，到一次正确的参数更新

[返回学习路线](../ROADMAP.md) · [M01/M02 课程](../curriculum/01-foundations-to-pretraining.md) · [实验脚本与结果](../experiments/002-token-weighted-loss/README.md)

适合：会基本 Python，想知道训练具体改变了什么的读者。预计 60–120 分钟完成阅读、手算和运行；是学习安排估计。无需 GPU、PyTorch、模型权重或 API。

本课是 M01/M02 的 worked example，同时为 M05 的分布式归一化埋下一个问题。它使用三维 logits 作为可更新参数，省去了产生 logits 的 Transformer；因此这里没有实现 attention、自动微分或完整语言模型。

## 1. 一次预测到底输出什么

假设词表只有 A、B、C，编号为 0、1、2。对于某个已经给定的上下文，模型输出三个未经归一化的分数，即 logits：

```text
z = [2, 1, 0]
正确的下一个 token = B，即 y = 1
```

softmax 将分数变成概率：`p_j = exp(z_j) / Σ exp(z_k)`。为避免大分数造成溢出，实际先减去最大的 logit，再求指数；所有分数同减一个常数不会改变概率。

| token | logit | 概率，约 |
|---|---:|---:|
| A | 2 | 0.665241 |
| B | 1 | 0.244728 |
| C | 0 | 0.090031 |

模型当前最偏向 A，但训练标签是 B。这里并不需要先随机采样一个答案再训练；监督目标直接使用正确标签的概率。

## 2. Loss 给这个预测怎样打分

单个目标的交叉熵是 `L = −log p_y`，使用自然对数。本例 `L ≈ 1.407606`。如果正确 token 的概率接近 1，loss 接近 0；正确 token 很不可能时，loss 变大。

先自己计算：如果概率是 `[1/3, 1/3, 1/3]`，loss 是多少？把 logits 全部加 1000，概率和 loss 应不应该变化？不要先看运行结果。

这还只是一个位置。真实 decoder 通常在很多位置预测下一个 token，还需要 shift labels、因果 attention 和有效目标 mask。M01 会说明这些位置的 logits 从哪里来。

## 3. 梯度告诉我们怎样改变参数

对 logits 的导数为：`∂L/∂z_j = p_j − 1[j=y]`。指示函数在 j 等于正确标签时为 1，其余为 0。本例梯度约为：

```text
[ 0.665241, -0.755272, 0.090031 ]
```

为什么 B 对应负数？梯度下降做 `z_new = z − η × gradient`，所以负梯度让 B 的分数增加，另外两个分数降低。取 `η=0.1`，本例一步后 loss 从 **1.407606 降到 1.307354**。

这里直接更新 logits，便于看清方向。在真实神经网络中，logits 是网络输出，反向传播还需通过链式法则把这个梯度传到各层权重。一步下降也不等于能泛化，更不证明任意学习率都会下降。

怎样独立检查导数？对参数分别加减一个很小的 h，用 `(L(z+h)-L(z-h))/(2h)` 近似导数。实验使用 h=`1e-5`，把有限差分与手写解析梯度对照；没有调用 autograd。

## 4. Mask 决定哪些目标参与学习

我们再构造六个位置。为了让数学容易核算，所有位置共享同一个三维参数 z；真实模型各位置输出通常不同。

| 位置 | 正确标签 | loss mask | 单位置 loss，约 |
|---:|---|---:|---:|
| 0 | A | 1 | 0.407606 |
| 1 | C | 1 | 2.407606 |
| 2 | C | 1 | 2.407606 |
| 3 | C | 1 | 2.407606 |
| 4 | B | 0 | 不计入目标 |
| 5 | A | 0 | 不计入目标 |

有效目标数是 4，整体 loss 应为：

`(0.407606 + 2.407606 × 3) / 4 ≈ 1.907606`

不能除以六个输入位置。实验还检查：改变最后两个被 mask 的标签，不改变 loss 和梯度；如果全部被 mask，脚本明确报错，要求调用方决定跳过还是诊断，而不是除以零或静默当成功更新。

**loss mask 不等于 attention mask。** 在真实 Transformer 中，一个不计自身预测 loss 的位置，仍可能作为后续预测的上下文，影响别的位置及网络梯度。工具观察通常不作为 agent 动作的监督目标，也仍可提供上下文。不能把这里的“忽略标签”外推成“输入 token 完全无影响”。

## 5. 设备更多时，一个很隐蔽的错误

把位置 0 放进组 A，其余放进组 B。组 A 有 1 个有效目标，组 B 有 3 个。它们各自的平均 loss 是 0.407606 和 2.407606。

如果把两个局部平均再平均，会得到 **1.407606**，与正确的 **1.907606** 不同。错误来自它给 A 组的一个 token 和 B 组的三个 token 相同总权重。

正确方式是保留每组的有效数量：

`L = (n_A × L_A + n_B × L_B) / (n_A + n_B)`

梯度也变了：正确共享参数梯度约为 `[0.415241, 0.244728, -0.659969]`，错误平均得到 `[0.165241, 0.244728, -0.409969]`。所以这不只是仪表盘显示差一点，而是模型在优化不同的加权目标。

如果每组有效数量相等，错误做法可能碰巧正确。这解释了为什么只测等长数据会漏掉问题。实验会改变分组，检查正确加权的 loss/梯度不变，并覆盖某一组全 mask 的情况。

这里的“错误”是相对于预先指定的全局 token 平均目标；如果研究有意让每组等权，那是另一个目标，需要明确声明并用相应标准评估。

此处的组只是同一 CPU 进程里的列表。真实 DDP/FSDP 还要核对 collective 是 sum 还是 average、梯度在哪个阶段缩放；不能直接复制这个公式后重复除以 world size。参见 [分布式训练章](../handbook/02-distributed-pretraining-operations.md)。

## 6. 运行并读结果

在 handbook 仓库根目录执行：

```powershell
python experiments/002-token-weighted-loss/run.py
```

脚本打印并保存 [results.json](../experiments/002-token-weighted-loss/results.json)。本次已在 Python 3.11.4 / CPU 执行：单位置和整批的有限差分最大误差都小于 `2e-11`；三种正确分组的结果一致；错误平均的反例、mask 和全 mask 检查通过。日期、完整数值与脚本 hash 在结果文件里。

不要只看到“通过”就结束。先找到 `ce_and_grad`、`aggregate`、`grouped` 三个函数，分别解释它们的输入输出；指出哪一行决定了有效 token 的权重，以及为什么有限差分能帮助发现推导或代码错误。

## 7. 读者练习与验收

以下练习留给学习者，不能因提供参考脚本就算完成：

1. 把正确标签改为 A，先预测梯度符号，再计算。答案应约为 `[-0.334759, 0.244728, 0.090031]`。
2. 把四个有效目标均匀分到两组，解释为什么 mean-of-means 此时相等；再构造另一个不等长反例。
3. 比较“被 mask 的标签改变”与“真实模型的上下文改变”，解释为什么前者无影响不能证明后者无影响。
4. 给全 mask batch 写一份调用方处理规则：记录什么、是否推进数据位置、怎样计数成功更新；说明规则不能替代框架实际行为。

均匀概率题的答案是 `log(3) ≈ 1.098612`；logits 同加常数不改变结果。完整验收是独立解释这些答案、复核一次梯度和一个分组反例，并写出本实验尚未覆盖的真实系统问题。
