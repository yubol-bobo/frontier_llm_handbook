# Harness 状态机实验


## 目的

这个小实验展示 provider 提议与 harness 执行权限之间的边界。确定性的模拟 provider 提议调用工具；harness 管理权限、有限的工具循环预算、调用 ID 和会话事件。这是原创教学模型，**并非对 Claude、Claude Code 或任何专有运行时的描述或复现**。

## 运行

需要 Python 3.10 或更新版本。在本目录执行：

```sh
python run.py
```

脚本运行八个独立的 `unittest` 测试。它只使用 Python 标准库和 CPU，无须安装包、凭据、付费 API、网络访问、子进程或真实的 shell／文件工具。启动 Python 本身是唯一需要执行的命令。

## 状态与执行

```text
requested → permission_checked → denied
                              ↘ started → result

恢复时存在 started 但没有 result → unknown（不自动重试）
```

`Session` 把不可变的 `Event` 记录追加到内存中的元组。旧快照保留原来的事件元组。`Snapshot` 包含模式版本、会话 ID、约束原文与事件；恢复时拒绝不支持的版本。调用 ID 由调用方提供的会话 ID 和已记录请求数生成。在单个线性会话中，恢复后的 ID 仍保持唯一；不同会话的 ID 需要调用方自行区分。

`dispatch()` 在记录 `started` 或调用工具之前，检查运行时由可信调用方提供的工具允许列表。未知工具会被拒绝。再次分派相同 ID 会复用已有的拒绝或结果，不调用工具。之后改变策略不会把旧的拒绝变成新调用。两个模拟工具是 `double` 和 `increment`；后者仅修改内存中的 `MockWorld.counter`。

循环首先检查是否存在已启动但没有结果记录的动作。如果存在，循环在查询 provider 之前就返回 `unknown`。否则，provider 完成或工具循环预算耗尽时，循环停止。每个新提议占用一个周期，被拒绝的提议也计数。达到上限会返回 `budget_exhausted`，即使 provider 在下一次查询中可能已经完成。该预算仅限制本次循环调用，不计量 token、费用、实际耗时或后续调用。

## 测试

| 测试 | 验证行为 |
|---|---|
| Provider 循环与权限顺序 | 完成两个提议；权限检查先于工具启动和结果记录。 |
| 复用拒绝 | 策略改变后，重复已拒绝的 ID 仍被拒绝。 |
| 复用结果 | 恢复后重复已完成的 ID 不重复副作用；下一个 ID 递增。 |
| 崩溃窗口 | 副作用发生但结果尚未记录；再次分派或恢复循环均报告 `unknown`，不重新执行。 |
| 有限预算 | 不断重复提议的 provider 在三个工具提议后停止。 |
| 压缩诊断 | 故意有损的摘要遗漏约束，检查器指出遗漏。 |
| 版本化快照 | 后续事件不会改变旧快照；未知版本被拒绝。 |
| 无效工具／调用 | 不支持的工具和不存在的调用 ID 均不产生副作用。 |

## 压缩与约束

压缩测试把历史概括为“Result was 6.”，故意遗漏“Do not increment the counter.”。`compact_context()` 同时返回摘要和遗漏的约束原文。会话快照仍然保留原始约束。

这是**检查原文是否保留的诊断**，并非语义验证：改写可能触发误报，包含原文但含义矛盾的摘要也可能通过。测试仅演示检测，不修复摘要，也不把自然语言约束自动转换成可执行规则。分派工具时使用的允许列表，是由调用方单独提供的策略输入。

## 运行范围与局限

这里的“重启”是从内存快照重建 `Session` 对象，同时保留同一个模拟世界。崩溃是在计数器改变后、结果事件追加前注入的异常。实验没有磁盘日志、进程重启、并发工作进程、真实模型、流式输出、沙箱或外部服务。快照是可信的本地数据，既未认证，也未经过完整的输入校验。使用元组追加是为了易读，而非高效率。

这**不保证恰好执行一次**。已标记 `started` 但没有结果的动作，可能已经发生、部分发生，也可能根本没发生；稳妥的报告是 `unknown`。新的调用 ID、独立会话、过期快照或分叉仍可能重复副作用。真实系统需要持久化记录，以及工具自身支持的状态核对或幂等机制。这个实验解释为什么不能盲目重试结果不明的副作用，并未实现这些生产环境机制。
